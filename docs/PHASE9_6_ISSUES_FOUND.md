- 真实/Mock：真实 Docker / MySQL / 浏览器

## ISSUE-002

- 严重级别：P1
- 发现阶段：通用网页图片解析代码审计
- 真实/Mock：代码审计 + 真实 MySQL 候选统计
- 复现步骤：检查 `web_ingest.py` 候选生成并统计 `image_candidate`。
- 预期：正文图片结合 alt、caption、DOM 上下文和附近正文判断与文章相关性。
- 实际：主要使用 URL、alt、尺寸和少量排除词；所有历史网页仅形成 1 个未审核候选。
- 根因：解析模型未保存图片附近正文/DOM 上下文，候选排序缺少可解释相关性分数。
- 修复：增加通用 DOM/前后正文上下文、文章主题 token、发现方式优先级和可解释相关性分数；V26 持久化上下文与分数，审核端展示，不写死站点选择器。
- commit：`e1856d1`
- 复测：AI 网页解析 20/20、后端图片集成 7/7、两端 typecheck/build 通过。
- 状态：FIXED

## ISSUE-003

- 严重级别：P1
- 发现阶段：真实 Docker / MySQL 历史网页重扫
- 真实/Mock：真实网络，新华网 4 篇已发布文章
- 复现步骤：临时只开启来源图片候选，执行历史补图重扫并查看文档 27、31 的候选。
- 预期：空 alt 的文章底部推荐图不应借用当前文章标题获得高相关性。

- 修复：相关性评分和候选持久化只使用图片真实 caption/上下文；文章标题仅可作为最终已选图片的无障碍文本兜底。
- commit：`17b1637`
- 复测：AI 21/21；清空后端 preview 缓存并复扫同一 4 篇文章，错误候选从 3 个降为 0；来源所有图片开关恢复关闭。
- 状态：FIXED

## ISSUE-004

- 严重级别：P1
- 发现阶段：大场镇真实 discover
- 真实/Mock：真实 Docker、MySQL 与宝山区政府信息公开目录
- 复现步骤：对来源 5 的部门目录执行 SECTION discover，最近 30 天、最多 20 篇。
- 预期：返回目录中的真实文章，并保留发布日期。
- 实际：修复前返回的 20 条候选主要是“政务公开”“按部门分类”和区属部门入口；真实文章被前置导航挤出结果。
- 根因：HTML 发现器按 DOM 顺序无差别接收所有同源链接，未识别导航/目录链接，也未把表格行的发布日期关联到文章。
- 修复：增加站点无关的文章 URL 信号、导航/目录负向信号和表格行日期提取；后端与机构端展示过滤数量。
- commit：`b93f019`
- 复测：离线目录回归筛出 2 篇文章并过滤 31 条导航；真实目录返回 4 篇近 30 天文章、过滤 82 条导航，0 个解析错误，来源在 finally 中恢复停用。
- 状态：FIXED
