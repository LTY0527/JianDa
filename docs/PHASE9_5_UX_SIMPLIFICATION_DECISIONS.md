# Phase 9.5 操作减法决策

## 管理员一级导航

原流程：工作台、材料管理、已发布内容、权威来源管理、公开信息导入、平台运营看板、操作日志并列。

为什么难理解：同一份内容在材料、导入和已发布三个入口间跳转；“权威来源”“公开信息导入”“平台运营”是系统实现概念，不是基层工作人员每天的任务。

新流程：工作台、内容中心、采集与来源、数据概览、系统记录。

- 一级入口从 7 项减少到 5 项。
- 已发布内容和网页导入保留原路由兼容，但不再占一级导航。
- 采集任务、来源白名单、调度和预算统一归入“采集与来源”。
- 真实指标从工作台移到“数据概览”。

## 工作台

原流程：先看处理中、待审核、正在公开、异常四个数字，再看 16 项试运营指标、近期材料和待审核列表，管理员需要自行判断优先级。

新流程：待审核、待发布、需要关注三个主行动数字，加一份按风险顺序生成的今日待办。

- 首屏主指标从 20 项减为 3 项。
- 失败、待审核、待发布分别提供直接行动按钮。
- `document_id`、任务编号、Token 和 Provider 不进入主工作台。
- 技术与运营指标保留在数据概览，不删除能力。

## 内容入口

原流程：上传材料去材料管理，网页导入去公开信息导入，发布结果去已发布内容。

新流程：进入内容中心，点击一次“添加内容”，选择上传 PDF/图片、粘贴网页链接或手工录入。

- 三类入口统一为一次选择，不重建第二套处理流程。
- 全部内容用待处理、待审核、待发布、已发布、异常状态查看。
- 开发 fixture 默认隐藏，仅显式开发开关可见。
- 网页来源安全、采集策略和 fixture 保留在平台管理员能力中，不暴露给普通审核员。

## 自动采集

原流程：进入来源管理后先看到来源列表、扫描与导入、AI 队列、采集任务和高级自动采集五个技术分区，普通工作人员需要理解发现方式、预算和任务状态才能找到“检查一次”。

新流程：默认只展示来源卡，卡片包含正常/需要关注/已停用、上次检查、发现新内容、下次检查、立即检查、查看新内容和自动更新。

- 日常检查无需切换技术 Tab。
- 最近失败和部分成功统一翻译为“需要关注”，具体错误仍可在高级设置查看。
- 来源核验、扫描范围、AI 队列、Token 预算、失败重试和历史补图全部移入“平台高级设置”。
- “立即检查”仍只发现 URL；影子采集不落库；立即采集才创建材料，且仍不自动发布。
- 原有白名单、SSRF、robots、限速、篇数和 Token 预算没有被删除或放宽。

## 审核与发布

原流程：审核员进入页面后逐项浏览全部 AI 字段，再进入发布表单，仅通过文字字段想象用户端最终效果。

新流程：审核页先给出“发现 N 项需要确认”，默认只展示尚未确认的字段；需要回看时再展开全部字段。发布页同步显示手机端预览，并可在普通字号和 24px 大字模式间切换。

- 已确认字段不再反复占据审核主视线，审核动作聚焦于未确认、低置信度和疑似重复风险。
- 原文、来源依据、图片人工审核和版本保护仍保留，没有绕过发布门槛。
- 发布预览直接复用当前材料的标题、摘要、结构化字段和步骤，不使用固定演示内容。
- 网页图片未完成人工审核时，发布按钮和流程仍被明确阻止。
