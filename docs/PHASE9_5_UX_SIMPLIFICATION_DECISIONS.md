# Phase 9.5 操作减法决策

## 管理员一级导航

原流程：工作台、材料管理、已发布内容、权威来源管理、公开信息导入、平台运营看板、操作日志并列。

为什么难理解：同一份内容在材料、导入和已发布三个入口间跳转；“权威来源”“公开信息导入”“平台运营”是系统实现概念，不是基层工作人员每天的任务。

新流程：工作台、内容中心、采集与来源、数据概览、系统记录。

- 一级入口从 7 项减少到 5 项。
- 已发布内容和网页导入保留原路由兼容，但不再占一级导航。
- 采集任务、来源白名单、调度和预算统一归入“采集与来源”。
- 真实指标从工作台移到“数据概览”。

## 工作台

原流程：先看处理中、待审核、正在公开、异常四个数字，再看 16 项试运营指标、近期材料和待审核列表，管理员需要自行判断优先级。

新流程：待审核、待发布、需要关注三个主行动数字，加一份按风险顺序生成的今日待办。

- 首屏主指标从 20 项减为 3 项。
- 失败、待审核、待发布分别提供直接行动按钮。
- `document_id`、任务编号、Token 和 Provider 不进入主工作台。
- 技术与运营指标保留在数据概览，不删除能力。

## 内容入口

原流程：上传材料去材料管理，网页导入去公开信息导入，发布结果去已发布内容。

新流程：进入内容中心，点击一次“添加内容”，选择上传 PDF/图片、粘贴网页链接或手工录入。

- 三类入口统一为一次选择，不重建第二套处理流程。
- 全部内容用待处理、待审核、待发布、已发布、异常状态查看。
- 开发 fixture 默认隐藏，仅显式开发开关可见。
- 网页来源安全、采集策略和 fixture 保留在平台管理员能力中，不暴露给普通审核员。
